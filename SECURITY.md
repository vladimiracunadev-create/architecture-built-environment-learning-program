# Política de seguridad

## Alcance técnico

Este repositorio publica material educativo, scripts de validación, workflows de GitHub Actions y un sitio estático. Un reporte de seguridad puede referirse, entre otros casos, a ejecución no prevista en los scripts, exposición de secretos, dependencias o acciones comprometidas, inyección de contenido en las páginas generadas o configuración insegura de GitHub Pages.

## Cómo reportar

Usa **Security → Report a vulnerability** en GitHub cuando esa opción esté disponible. Si el hallazgo contiene una prueba explotable, una credencial, datos personales o información de terceros, no lo publiques en un issue. Incluye el componente afectado, condiciones de reproducción, impacto observado y una propuesta de mitigación si la tienes.

Las erratas, enlaces rotos, fuentes discutibles o desacuerdos pedagógicos no son vulnerabilidades: pueden informarse mediante un issue sin datos sensibles.

## Seguridad del contenido educativo

Los ejemplos del currículo no autorizan inspecciones, ensayos, intervenciones ni obras reales. Tampoco reemplazan cálculo, especificación, revisión de especialidad, permiso, supervisión ni normativa vigente. Toda actividad profesional debe contar con competencias, responsabilidades, instrumentos, procedimientos y autorizaciones aplicables al caso y a su jurisdicción.

No incluyas en contribuciones planos sensibles, ubicaciones de infraestructura crítica, credenciales, datos personales, información contractual reservada ni instrucciones operativas que creen un riesgo injustificado.

## Respuesta esperada

Los reportes se evaluarán según reproducibilidad, impacto y alcance. Una corrección técnica podrá acompañarse de regeneración del sitio, validación integral y una nota de cambio. Esta política no promete un plazo de respuesta ni constituye un programa de recompensas.
